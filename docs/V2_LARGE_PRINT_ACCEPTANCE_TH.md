# NiyomSilp Design v2 — เกณฑ์ตรวจรับระบบภาพใหญ่สำหรับร้านป้าย

เอกสารนี้ใช้ตรวจเฉพาะ **การขยายภาพขนาดใหญ่และการส่งออกงานพิมพ์** โดยไม่เปลี่ยน v1 stable และไม่ถือว่าการเพิ่มจำนวนพิกเซลเท่ากับการสร้างรายละเอียดภาพใหม่ทั้งหมดด้วย AI

## หลักการที่ต้องผ่าน

1. ห้ามลดขนาดพิกเซลปลายทางอัตโนมัติเพียงเพราะเกิน 120,000 px ต่อด้าน หรือ 450 ล้าน px รวมซึ่งเป็นเพดานเก่าของ v1
2. ให้คำนวณจำนวนพิกเซลจาก **กว้าง × สูง × หน่วย × DPI** หรือจากอัตราขยายที่ผู้ใช้พิมพ์เอง แล้วแสดงขนาดปลายทางก่อนเริ่ม
3. ภาพใหญ่ต้องใช้การอ่าน/ประมวลผล/ส่งออกแบบแบ่งส่วนบนดิสก์ ไม่สร้างภาพเต็มทั้งหมดใน RAM/GPU โดยไม่จำเป็น
4. อัตราขยาย 2x/4x/8x ใช้เส้นทาง AI ที่กำหนดไว้; เป้าหมายสูงกว่า 8x ต้องแจ้งว่าเป็นการปรับขนาดปลายทางเพิ่มเติม ไม่รับประกันการสร้างรายละเอียดใหม่ตามตัวคูณทั้งหมด
5. การล็อกอัตราส่วนต้องรักษาสัดส่วนตามโหมด Fit; ปลดล็อกให้เต็มพื้นที่ตาม Stretch โดยไม่เปลี่ยนตัวเลขขนาดที่ป้อน
6. หากพื้นที่ดิสก์ไม่พอ ต้องแจ้งสาเหตุแทนการลด DPI/ขนาดเอง และห้ามทำให้ไฟล์ปลายทางเดิมเสียหาย
7. ถ้า JPG ไม่รองรับด้านภาพที่ร้องขอ ให้แจ้งเปลี่ยนเป็น PNG, TIFF/BigTIFF หรือ PDF; ห้ามลดพิกเซลเงียบ ๆ
8. Preview/Fit/1:1 ต้องดูได้โดยไม่จำเป็นต้องอ่านภาพทั้งไฟล์มาเก็บใน RAM
9. การกด Stop ระหว่างทำงานต้องหยุดอย่างปลอดภัยและล้างไฟล์ชั่วคราว โดยไม่แทนที่ไฟล์เก่าด้วยผลที่ยังไม่สมบูรณ์
10. Windows installer ต้องแพ็ก pyvips/libvips, tifffile, โมเดล และ DLL ที่จำเป็นครบ พร้อมตรวจรันจากโปรแกรมที่ติดตั้งจริง

## ตัวอย่างทดสอบจากโค้ด

| กรณีทดสอบ | สิ่งที่ต้องตรวจ |
| --- | --- |
| ขนาดงาน 700 × 100 ซม. 300 DPI | PNG จริง 82,677 × 11,811 px และ DPI 300; เป็นงานที่เกินเพดาน 450 ล้าน px ของ v1 |
| แถบภาพยาว 130,001 × 2 px | PNG ต้องสร้างได้และรักษาความกว้างเกินเพดาน 120,000 px |
| นำเข้าต้นฉบับ 20,000 × 10,000 px | Preview และส่งออกขนาดเดิมได้โดยไม่โหลดภาพเต็มเข้า RAM |
| ตั้งอัตราขยายเอง 16x / 32x | UI แสดงจำนวนพิกเซลปลายทางจริง; ไม่ใช้เพดานของ v1 |
| AI 2x / 4x / 8x และเป้าหมาย 16x | ตรวจขนาดจริง, สัดส่วน, ลำดับ pass, context รอยต่อ Tile และความต่างด้านคุณภาพ |
| Stop หรือ error ขณะประมวลผล | ไฟล์เก่าคงอยู่ ไม่มีไฟล์ .niyomsil_* ค้าง |
| Export TIFF/BigTIFF/PDF | เปิดด้วยโปรแกรมปลายทางแล้วตรวจขนาดจริง สี และ DPI |

## การตรวจรับบนเครื่องร้าน

- [ ] ติดตั้ง EXE บน Windows 64-bit โดยไม่ต้องติดตั้ง Python เอง
- [ ] เปิดแอปและลากภาพงานป้ายจริงเข้าได้
- [ ] ตั้งกว้าง/สูง/หน่วย/DPI และ 16x หรือ 32x แล้วจำนวนพิกเซลแสดงตรงตามค่าที่ตั้ง
- [ ] ใช้งานอย่างน้อยหนึ่งภาพที่เคยหยุดเพราะเพดาน 450 ล้านพิกเซล โดยทดสอบแบบ **ไม่ใช้ AI ก่อน** เพื่อแยกปัญหา I/O ออกจากประสิทธิภาพ GPU
- [ ] เปิดไฟล์ PNG/TIFF ที่ส่งออกแล้วตรวจพิกเซลจริง ไม่ใช่ดูแค่ Preview
- [ ] ตรวจสี ตัวอักษรไทย รอยต่อ Tile และความคมชัดกับภาพงานร้านที่ใช้จริง
- [ ] ตรวจการประมวลผล AI บน CPU และอุปกรณ์ GPU ที่มีอยู่จริง
- [ ] ทดสอบ Stop และพื้นที่ดิสก์ไม่พอ โดยตรวจว่าไฟล์งานก่อนหน้ายังเปิดได้
- [ ] ตรวจตัวติดตั้งและการถอนติดตั้งจริง รวมถึงค่า SHA-256 ใน release

## ข้อจำกัดที่ต้องสื่อสารตรงไปตรงมา

ไม่มีเพดาน **ที่ตั้งเองในโปรแกรม v2** แบบ v1 ไม่ได้แปลว่าไฟล์ภาพทุกขนาดเป็นไปได้ทางเทคนิค: ตัวเข้ารหัส พื้นที่ดิสก์ หน่วยความจำ ระบบไฟล์ ความยาวพิกัดของ libvips/PDF และเวลาในการประมวลผลยังเป็นข้อจำกัดจริง ภาพตัวอย่างใน CI เป็นกรณีเฉพาะ และยังต้องทดสอบไฟล์ร้าน/เครื่อง GPU ก่อนยืนยันว่า v2 พร้อมใช้งานจริง
