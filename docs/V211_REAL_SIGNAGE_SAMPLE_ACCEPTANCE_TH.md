**ไฟล์ที่ส่งมาเป็นตัวอย่าง “ประเภทงานป้ายที่โปรแกรมต้องรองรับ” ไม่ใช่งานให้ตรวจชื่อไฟล์หรือ DPI ของตัวอย่าง** เนื้อหาสำคัญคือต้องพัฒนาการฟื้นคุณภาพภาพ raster ที่ได้จาก AI/ลูกค้าให้ดีขึ้นกว่า Approved V2 โดยไม่เปลี่ยนรูปแบบงานเดิม การตรวจพิกเซล/DPI/ICC จึงเป็นขั้นตอนส่งออกงานพิมพ์ภายหลัง **ไม่ใช่เกณฑ์หลักเพื่อวิเคราะห์ภาพตัวอย่างชุดนี้** และห้ามอนุมานคุณภาพจากชื่อไฟล์

### แยก 3 แนวทางที่ต้องพัฒนาและทดสอบจริง
1. **Verified Text สำหรับข้อความเล็กทั่วไป**: นำผลที่ผู้ใช้เห็นว่าดีขึ้นมาต่อยอดให้ตัวอักษรเล็กอ่านง่ายขึ้น; เมื่อทราบ *ข้อความและฟอนต์ตรงต้นฉบับ* จึงให้ผู้ใช้เปิดโหมดสร้างใหม่ได้ตามสมัครใจ. เมื่อไม่ทราบต้นฉบับหรือ OCR ไม่มั่นใจ ให้พยายามเพิ่มความชัดแบบรักษาตัวอักษรเดิมและแสดงความไม่แน่นอน; ห้ามเดาคำหรือวรรณยุกต์แล้วแทนข้อความโดยอัตโนมัติ
2. **Styled/Effect Typography ที่ rasterized จาก AI**: ไม่ flatten และไม่ render เป็นข้อความสีเดียว; ฟื้นขอบตัวอักษร/ขอบตัดสี **คมและต่อเนื่อง** โดยรักษาไล่สีภายใน **นุ่มเนียน**, รายละเอียดสี เงานุ่ม แสงเรือง มิติ 3D ลายนูน และขอบซ้อนด้านนอก. ลดเม็ดสี/noise/คราบ/แถบสีโดยไม่ลบรายละเอียดที่เป็นเอฟเฟกต์ตั้งใจ และไม่ทำให้สีไหลข้ามขอบ
3. **องค์ประกอบลายไทย/ทอง/ผ้า/พื้นหลังและ PNG โปร่งใส**: เกลี่ยสีและกู้รายละเอียดโดยรักษาเส้นโค้ง ปลายลายกนก เส้นแกะทอง ไฮไลต์/เงาทอง ความนุ่มผ้า และขอบโปร่งใส; ห้าม AI เพิ่มลายหรือลบลายเดิม. ทดสอบร่วมกับภาพถ่าย บุคคล และสินค้าสำหรับภาพป้ายทั้งภาพ

**ลำดับตัดสินคุณภาพ:** (1) ไม่เสียรูปทรง/ข้อความ/เอฟเฟกต์/ลายไทย/สี (2) คมและเนียนขึ้นจริงเมื่อเทียบ Approved V2 ด้วยการตรวจภาพ 100% และขนาดใช้งาน (3) ไม่มี artifact ใหม่ (4) ค่อยตรวจ DPI/ICC/การส่งออกตามขนาดงานของลูกค้า. ห้ามสรุปว่าดีกว่า V2 จากผล Verified Text เพียงกลุ่มเดียว

## เป้าหมายที่ผู้ใช้ยืนยัน
งานต้นทางมักเป็น **ภาพแบน (flattened raster) จาก AI หรือลูกค้า** ไม่ได้มีเลเยอร์ข้อความหรือฟอนต์จริง โจทย์หลักคือขยาย/กู้ภาพทั้งภาพเพื่อพิมพ์ไวนิล: ขอบคมขึ้น พื้นสีเนียนขึ้น เม็ดรบกวนลดลง **โดยคงตัวหนังสือเอฟเฟกต์ (ไล่เฉด ขอบหลายชั้น เงา นูน 3D แสงเรือง), ลายไทย/ทอง, ผ้า, ภาพสินค้า, ใบหน้า และพื้นที่โปร่งใส** ให้เหมือนงานต้นฉบับ ไม่ใช่พิมพ์ข้อความธรรมดาทับลงไป

คุณภาพสำคัญกว่าความเร็ว; GTX 1660 Ti 6 GB เป็นสภาพแวดล้อมทดสอบ ไม่ใช่เพดานการเลือกโมเดล สามารถทดสอบ CPU/RAM offload, งานแบ่ง tile, disk-backed buffer และการประมวลผลหลายรอบได้เมื่อปลอดภัยและวัดผลจริง; ห้ามอ้างว่ารันสำเร็จโดยยังไม่ได้ทดสอบ

## ชุดไฟล์อ้างอิงที่ได้รับและ preflight
- ภาพเปรียบเทียบตัวอักษรทั่วไป 2 ภาพ: แสดงแนวทาง Verified Text แบบทราบข้อความ/ฟอนต์ **ไม่ใช่หลักฐานกู้ข้อความเอฟเฟกต์จากไฟล์ลูกค้า**
- ป้าย JPEG ออกแบบสำเร็จ 5 ภาพ: ตัวอักษรสี/ไล่เฉด/ขอบซ้อน ข้อความไทยขนาดเล็ก ภาพอาหาร/สินค้า/บุคคล และองค์ประกอบมากชนิด รูปมีขนาดตั้งแต่ 682×2048 ถึง 1774×887 พิกเซล (มีตัวอย่าง 1499×1049, 1054×1492)
- องค์ประกอบ PNG แบบ RGBA 4 ภาพ: กรอบทอง 2048×249, พานผ้าไตร 2048×873, กรอบล่าง 2000×528, ม่านบน/ข้าง 2048×1260 พิกเซล; มี alpha จริง โดยพบทั้งบริเวณโปร่งใสเต็มและโปร่งใสบางส่วน
- **ข้อค้นพบสำคัญ:** PNG ทั้ง 4 **ไม่พบแท็ก DPI หรือ ICC ที่ฝังในไฟล์** แม้ชื่อไฟล์มี “200ppi” และไฟล์ JPEG ส่วนใหญ่มี DPI metadata เท่ากับ 72 (ไม่ใช่การยืนยันคุณภาพงานพิมพ์จริง) จึงต้องกำหนดกว้าง×สูงจริงก่อนคำนวณ effective PPI; จากการอ่าน alpha histogram ส่วนใหญ่ของพิกเซลที่มีภาพอยู่เป็น alpha 250–254/255 (เกือบทึบ) และบางบริเวณเป็นขอบกึ่งโปร่งใส; **ค่า alpha ไม่เต็ม 255 ไม่ถือเป็นข้อผิดพลาดเอง** ต้องดูภาพซ้อนพื้นดำ/ขาว/แดงและเทียบ V2 ก่อนประเมิน halo/fringe
- ห้ามนำภาพเหล่านี้ไปสรุปว่า V2.1.1 ดีกว่า V2: ยังไม่มีคู่ผลการประมวลผลจาก V2 และ V2.1.1 ที่ทำในสภาพเดียวกันสำหรับไฟล์ชุดนี้

| กลุ่ม | ตัวอย่างต้องทดสอบ | เกณฑ์ผ่าน / Hard-fail |
|---|---|---|
| A. Plain/verified text | ตัวอักษรไทย/อังกฤษที่ทราบข้อความและฟอนต์ | อักษรและวรรณยุกต์ตรงเดิม, เส้นคมกว่า V2; โหมดนี้เป็น opt-in และไม่ทับตัวอักษร FX |
| B. FX typography flattened | ตัวอักษรไล่สี ขอบนอก 1–3 ชั้น ฟองนูน 3D แสงขอบ เงานุ่ม และตัวเลขราคา | รูปทรง/สระ/วรรณยุกต์/ราคาไม่เปลี่ยน, ขอบนอกไม่กินเนื้ออักษร, ไล่สีไม่มีเม็ด/คราบน้ำเงิน-ดำ/banding, เงา/Glow ยังนุ่มตามเดิม; **เสียองค์ประกอบใด = ไม่ผ่าน** |
| C. ภาพสินค้า/อาหาร/บุคคล | ภาพน้ำกระเซ็น ผิวอาหาร บรรจุภัณฑ์ ใบหน้า | มีรายละเอียดที่เป็นธรรมชาติ ไม่สลับตัวตน ใบหน้า ตา ปาก โลโก้ หรือข้อความบนสินค้า |
| D. Thai ornament + transparent PNG | ขอบทอง ลายกนกปลายแหลม ม่านแดง ผ้าไตร พานและดอกไม้ | ลายไม่ละลาย/ไม่ขาด, สีทองมีมิติ ไม่เกิดเส้นสีแปลก, รักษาความนุ่มของผ้า/รอยพับ, alpha/ขอบโปร่งใสถูกต้องบนพื้นขาว/ดำ/แดง |
| E. Whole-image + large-format | งานเต็มและ crop 100%, 2×/4×, หลาย tile; ขนาดพิมพ์จริง | ไม่มีรอยต่อ tile, ฮาโล่/oversharpen, วัตถุเสียรูป, ไม่มีการเปลี่ยนพื้นหลังหรือสีผิดไปจากเจตนา; ยืนยันขนาดและไฟล์ PNG/TIFF/PDF |
| F. Print workflow | 150/200/300/600 PPI ตามขนาดจริงที่เลือก | ตรวจ **พิกเซลจริง** = (กว้างซม. ÷ 2.54) × PPI และสูงเช่นเดียวกัน; ใส่ DPI tag ตามสเปก, ICC ที่เลือกต้องรักษา, ตรวจ Photoshop/MainTop และพิมพ์ทดสอบก่อนรับรอง |

### กติกาเปรียบเทียบ V2 ↔ V2.1.1
1. เก็บต้นฉบับแบบ private และทำ 3 คอลัมน์ **ต้นฉบับ / V2 รุ่นผ่าน / V2.1.1 ทดลอง** ที่จำนวนพิกเซลปลายทาง, ICC และ PPI เท่ากัน; ห้ามเทียบภาพจากคนละ scale หรือคนละตัวอย่าง
2. ตัด crop มาตรฐานที่ขอบตัวอักษร เส้นไล่สี สระ/วรรณยุกต์ ขอบทอง ปลายลายกนก ใบหน้า และ alpha; ตรวจที่ 100% และที่ขนาดมองงานพิมพ์
3. เก็บ metric เฉพาะที่มี reference จริง (เช่น PSNR/SSIM), สี/ขอบ/แถบสี/alpha/ความต่อเนื่องของ tile, พร้อม **visual approval**. คะแนนดีขึ้นเฉลี่ยไม่สามารถลบล้างข้อผิดพลาดรุนแรงเฉพาะจุด
4. ความเสียหายของความหมาย/ราคา/ใบหน้า/ขอบอักษร/alpha หรือโลโก้ = Hard fail. หาก V2.1.1 ด้อยกว่า V2 ในบริเวณใด ให้ทิ้งผลทดลองส่วนนั้นและคง V2 อย่างเปิดเผย; ไม่มีการรับรองว่าระบบนี้ implemented แล้ว
5. การขยายให้ถึง 150–600 PPI เป็นการจัดส่งจำนวนพิกเซลตามขนาด ไม่ใช่สัญญาว่า AI กู้รายละเอียดที่ไม่มีในต้นฉบับได้ทั้งหมด

- source-only/test synthetic ที่รันในสภาพแวดล้อมตรวจสอบผ่าน 9 กรณี; รอผล GitHub Actions สำหรับ commit ล่าสุดก่อนกล่าวว่า CI ผ่าน; **real model A/B บนภาพเหล่านี้ = ยังไม่ทำ**

ตัวอย่างคำสั่ง (เก็บไฟล์ลูกค้าไว้ภายในเครื่อง):
```bash
python -m tools.v211_signage_roi_audit --source private/input.png --regions private/regions.json --out private/source-review
python -m tools.v211_signage_roi_audit --source private/input.png --v2 private/v2.png --super private/v211.png --regions private/regions.json --out private/ab-review
```

```json

```
